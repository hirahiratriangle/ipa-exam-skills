# IPA試験の技術解説をつくる

対策アプリの学習モードに取り込む解説の JSON を、IPA が公開している PDF から作る。

出力は 1 ファイル（`<区分>_notes.json`）。問題のファイルとは別で、別々に取り込める。
**解説を直しても問題には触らない。** 逆も同じ。更新の頻度が違うので分けてある。

## 問題の解説とは役割が違う

問題にも `explanation` があるが、あれはその1問に閉じた文章で、「なぜこの答えか」しか
書けない。それを読んで概念が身につくことはない。

こちらは**問題を解く前に読む教材**である。学習モードは、解説を時間を決めて読ませた
あと、同じ範囲から10問出す。読む段階では設問も選択肢も見せない。だから解説は、
設問に依存しない独立した読み物として成り立っていなければならない。

## 何よりも先に：推測で書かない

このアプリの値打ちは、出題範囲が IPA の公開資料に裏付けられていることにある。
記憶から書くと、範囲外の用語や、古い制度の記述や、現行シラバスから消えた話題が
混ざる。混ざっても見た目は正しいので、読んでいる本人は気づけない。

だから**必ずシラバスを読んでから書く**。手順は「資料を読む」の節にある。

## 出力する JSON

```json
{
  "notes": [
    {
      "category": 11,
      "topic": "情報セキュリティ",
      "title": "共通鍵暗号と公開鍵暗号",
      "body": "本文。2000〜3000字の地の文。段落は空行で分ける。",
      "source": "シラバス Ver.8.0 中分類11 情報セキュリティ"
    }
  ]
}
```

解説だけのファイルなので `questions` は入れない。**入っていない側は取り込みで
触られない**ため、問題は現状のまま残る。

書き出したら `python3 -m json.tool <ファイル>` で構文を確かめる。
説明文やコードブロックの記号（```）をファイルに混ぜない。取り込みで弾かれる。

## 資料を読む

資料（IPA の公開 PDF）は利用者が好きなフォルダに集めてある。依頼でフォルダを指定
されたらそこを、無ければ作業ディレクトリの下を `find . -iname '*.pdf'` で探す。
見つからない、または下の表の資料が足りないときは、何が足りないかを伝えて置き場所を
聞く。**資料が揃うまで書き始めない。** 以降「資料フォルダ」はここで決めたフォルダを指す。

`pdftotext -enc UTF-8 -layout` で抽出すると、節の階層や用語例が崩れずに読める。
入っていなければ（`command -v pdftotext`）、macOS なら `brew install poppler`、
Debian/Ubuntu なら `sudo apt install poppler-utils` を案内する。

```bash
pdftotext -enc UTF-8 -layout "<資料フォルダ>/syllabus_fe_ver8_0.pdf" - | less
```

| 資料 | 何が確定するか |
|---|---|
| シラバス | 小分類ごとの学習目標と用語例。**解説の種はここ** |
| 試験要綱 | 出題範囲の階層、分類の番号、科目Bの内訳 |
| 試験用語 | 出題で使う用語と表記。言い回しに迷ったら |
| 公開問題 | その小分類で実際に何が問われるか。厚く書く対象を決める材料 |

公開問題は参考であって、解説の種はシラバスの用語例である。問題冊子が画像だけの
PDF の区分（応用情報など）では、解説を書くために無理に OCR する必要はない。

### 抽出したテキストは、そのまま貼らない

pdftotext は PDF のルビを独立した行として吐く。`脆弱性` は `ぜい` が前の行に、
`誤謬` は `びゅう`、`虹彩` は `こう`、`秘匿` は `とく` が出る。気づかず本文に貼ると
`ぜい` が紛れ込み、しかも JSON としては通るので取り込むまで分からない。
ページ区切りの `- 12 -` とコピーライト行も文の途中に割り込む。
**貼る前に、ルビ・ページ番号・コピーライト行を取り除く。**

## 分類の番号

`category` はアプリの分類マスタの番号に合わせる。番号がずれていても科目さえ合って
いれば取り込みは通ってしまい、見出しと中身が食い違った教材が居座る。

基本情報の科目Aは次の 1〜23。ほかの区分はその区分の要綱から起こし直す。

1 基礎理論 / 2 アルゴリズムとプログラミング / 3 コンピュータ構成要素 /
4 システム構成要素 / 5 ソフトウェア / 6 ハードウェア /
7 ヒューマンインタフェース / 8 マルチメディア / 9 データベース /
10 ネットワーク / 11 セキュリティ / 12 システム開発技術 /
13 ソフトウェア開発管理技術 / 14 プロジェクトマネジメント /
15 サービスマネジメント / 16 システム監査 / 17 システム戦略 /
18 システム企画 / 19 経営戦略マネジメント / 20 技術戦略マネジメント /
21 ビジネスインダストリ / 22 企業活動 / 23 法務

**科目Bは科目Aとは別の分類**になる。基本情報なら要綱の科目B出題範囲に沿って
101〜105（プログラミング全般／処理の基本要素／データ構造及びアルゴリズム／
諸分野への適用／情報セキュリティの確保）を使う。科目Bの解説もこの番号で書く。

### 小分類の一覧と並び順も、マスタが正

`topic` に入れる小分類名は、**その一覧と並び順の正をシラバスPDFではなくアプリの
分類マスタ（`<アプリ>/data/categories.py` の `TOPICS`）に置く。**

シラバスPDFから自分で起こすと取りこぼす。見出しの番号の後が半角の `.` のところと
全角の `．` のところが混在していて、`^\s*(\d+)\.` で拾うと後者が落ちる。基本情報では
中分類17の「業務プロセス」だけがこれに当たり、96個あるはずが95個になった。1個足りない
ことは、数えてマスタと突き合わせるまで分からない。

```bash
python3 -c "
import importlib.util
spec = importlib.util.spec_from_file_location('c', '<アプリ>/data/categories.py')
m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
for c, ts in sorted(m.TOPICS.items()): print(c, ts)
"
```

**学習モードの並び順はこのマスタの順で決まり、マスタに無い小分類名は末尾に回される。**
だから `topic` を1字でも違えて書くと、その解説だけが学ぶ順から外れる。

## 解説を書く

- 1本あたり **2000〜3000字**。短くまとめようとしない。書き終えたら字数を数えて確かめる。
  **書いた直後はほぼ必ず足りない。** 段落は1つ140字前後にしかならないので、2000字には
  **15〜18段落**が必要になる。10段落ほどで「書けた」と感じたら1500字前後で、500字以上
  足りていない。先に段落の数で見積もり、足りなければ具体例、数値を入れた計算、
  混同しやすい概念との違い、実務での落とし穴を段落として足す。要約して縮めるのは逆
- `topic` は**シラバスの小分類名**をそのまま入れる（「情報セキュリティ」
  「データベース設計」など）。問題側の `topic` も同じ粒度で揃える。
  学習モードが小分類の一致で出題を選ぶため
- 見出し（`title`）のほうは自由に絞ってよい。「共通鍵暗号と公開鍵暗号」のように、
  1本で扱う話題を表す
- **小分類の用語を全部は説明しきれない。** 中分類11の小分類「情報セキュリティ」だけで
  用語例は150ほどあり、3000字では1語20字にしかならない。
  出題数の多いものと、混同されやすいものを選んで厚く書く。
  1本に詰め込まず、同じ小分類で `title` を変えた解説を複数本つくってよい
- 順番は、**なぜ必要になったか → 定義 → しくみ → 具体例や数値 →
  使いどころと使い分け → 混同しやすい概念との違い**
- 用語を出したらその場で説明する。知っている前提で使わない
- しくみは動きを順を追って書く。「〜という方式である」で止めない
- 計算がからむなら、式を示したうえで具体的な数値で1回計算してみせる
- 混同しやすい概念は「どちらがどう違うか」を正面から書く。試験ではそこが問われる
- 設問・選択肢・正解には触れない。概念そのものを説明する

**`notes` はシラバスの小分類順に並べる。** 学習モードは、中分類の中の解説を
取り込んだ順に出す。順番がばらばらだと、学ぶ順もばらばらになる。

**Markdown を使わない。** `#` や `-` や `**` を書くと、記号がそのまま画面に出る。
アプリは本文を素通しで表示し、改行と全角スペースだけを保つ。段落は空行で分ける。

**自分で書いた文に、日本語以外の文字が混じることがある。** 「группы」「четвёртый」
「점수」のような語が、意味の通る位置に紛れ込む。JSON としては通り、2000字の地の文を
読み返しても気づきにくい。書き出したら機械で走査する。

```bash
python3 -c "
import json, re
for x in json.load(open('<区分>_notes.json', encoding='utf-8'))['notes']:
    bad = re.findall(r'[\u0400-\u04FF\uAC00-\uD7AF]+', x['body'])
    md = [c for c in ('#', '**') if c in x['body']]
    print(len(x['body']), x['topic'], bad, md)
"
```

読んだ人が同じ小分類の問題を初見で解けることを目安にする。

## 書き足す・厚くするとき

苦戦している分野の解説を厚くする、といった部分的な依頼が多い。手順は決まっている。

1. **既存の `<区分>_notes.json` を読む。** 何本あり、どの小分類にどの `title` が
   あるかを把握する
2. 直す本の `body` を書き換える、または `title` を変えた本を足す
3. **全件を1ファイルに書き出す。** 取り込みはファイルに無い行を消すので、
   直した数本だけのファイルを渡すと残りが消える

**`title` は変えない。** 取り込みは category ＋ title を鍵にして突き合わせる。
title を変えると別の解説として扱われ、「どの解説を読んだか」の履歴が切れる。
`body` の加筆や `topic`・`source` の直しは、同じ行の更新として扱われる。

同じ小分類に複数本あるときは、`title` で扱う話題を区別する。本数が増えてきたら、
読む順に並んでいるかを確かめる。**アプリは同じ小分類の解説をまとめて続けて読ませる**
（出題が小分類ごとなので、読む単位もそこに合わせてある）。2本なら読む量は倍になる。
並ぶのはアプリに登録された順なので、あとから追加で取り込んだ解説は、JSON の中で
前に置いても後ろに回る。

## 分量の目安

| 依頼 | notes |
|---|---|
| 試しに1本 | 1本 |
| 分野をひとつ | その中分類の小分類ぶん（数本） |
| 全分野を一度に | 小分類ごとに1本（基本情報なら約96本） |

全分野を一度に書くと 1 本の会話では収まらない。中分類ごとに書いて部品を
資料フォルダの `作業中/` に残し、最後に1ファイルへまとめる。次に一部だけ
書き直すときにも使える。

**解説1本には、その小分類の問題10問が対になる。** 学習モードは解説を読ませたあと
同じ小分類から10問出すので、問題が足りなければ短いラウンドになる。さらに**問題が
0問の小分類の解説は、解説の一覧にも出ない**（`pick_note` が問題のある小分類に絞る）。
だから解説だけを先に書いても、問題を足すまで学習モードには現れない。

書く順はどちらからでも成り立つ。解説を先に書くと、その小分類で何を問うべきかが
固まるので作問が速い。どちらを先にしても、**取り込みは2ファイル揃ってから一度に行う**
（取り込みは入っていない側に触らないので、途中の状態をアプリに作らずに済む）。

既にある解説の字数を点検するときは、全件の字数を並べて 2000 を下回る本を数える。
過去に書いた分がまとめて足りていないことがある。

どこまで作るかは使う人が決めること。指定がなければどの分野を何本作るか先に聞く。
**全小分類を網羅するなら、問題も小分類 × 10問が必要になることを先に伝える。**
基本情報なら解説96本と問題960問前後で、分量が大きく違う。

## 出来たら

**書き出し先は資料フォルダ**（指定があればそこ）。区分と中身が分かる名前を付ける
（`fe_notes.json`・`ap_notes.json`）。更新するときは同じ名前へ上書きし、前の版を
残したいときは控えを別名で取る。

書き出したファイルの場所と、何本入っているかを伝える。取り込みは管理用の ID
（is_admin）で入った人が画面から行う。ほかの ID には入口が出ない。

```
アプリ → 問題の管理 → JSONを取り込む → ファイルを選ぶ
```

取り込みは**鍵で突き合わせる同期**で、確定の前に追加・更新・変更なし・削除の件数が
出る。**削除の件数が想定より多ければ取り込まない。** 書き出した範囲が足りていない
合図である。解説を含むファイルを取り込んでも、問題と解答履歴には触らない。
