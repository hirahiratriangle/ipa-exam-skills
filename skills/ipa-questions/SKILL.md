# IPA試験の問題をつくる

対策アプリに取り込む問題の JSON を、IPA が公開している PDF から作る。

出力は 1 ファイル（`<区分>_questions.json`）。科目Aと科目Bの両方をここに入れる。
学習モードで読ませる技術解説は別のファイルで、**`ipa-notes` スキル**が受け持つ。
問題を入れ替えても解説には触らない。更新の頻度が違うので分けてある。

## 何よりも先に：推測で書かない

このアプリの値打ちは、出題範囲と正解が IPA の公開資料に裏付けられていることにある。
記憶から書くと、範囲外の用語や、古い制度の記述や、微妙に違う正解が混ざる。
混ざっても見た目は正しいので、解いている本人は気づけない。

だから**必ず PDF を読んでから書く**。手順は「資料を読む」の節にある。

## 出力する JSON

```json
{
  "questions": [
    {
      "category": 11,
      "subject": "A",
      "topic": "情報セキュリティ",
      "difficulty": 2,
      "stem": "問題文",
      "choices": ["アの本文", "イの本文", "ウの本文", "エの本文"],
      "answer": 0,
      "explanation": "正解の理由と、他の選択肢がなぜ違うか",
      "source": "令和6年度 科目A 問35"
    }
  ]
}
```

`questions` だけの素の配列（`[ ... ]`）でも取り込める。解説は入れない。
**入っていない側は取り込みで触られない**ため、解説は現状のまま残る。

取り込みは鍵で突き合わせる同期で、問題は subject ＋ category ＋ stem が鍵になる。
choices や answer、explanation、difficulty の直しは同じ行の更新として扱われ、
その問題の解答履歴も途切れない。一方で **stem を書き換えると別の問題になり、
その問題の履歴は消える**。文言を練り直すときは、それを承知で変える。

ファイルに無い行は消えるので、**一部だけを書き出したファイルを取り込ませない。**
その区分の全問を1ファイルに入れる。

書き出したら `python3 -m json.tool <ファイル>` で構文を確かめる。
説明文やコードブロックの記号（```）をファイルに混ぜない。取り込みで弾かれる。

## 資料を読む

資料（IPA の公開 PDF）は利用者が好きなフォルダに集めてある。依頼でフォルダを指定されたら
そこを、無ければ作業ディレクトリの下を `find . -iname '*.pdf'` で探す。見つからない、
または下の表の資料が足りないときは、何が足りないかを伝えて置き場所を聞く。
**資料が揃うまで書き始めない。** 以降「資料フォルダ」はここで決めたフォルダを指す。

`pdftotext -enc UTF-8 -layout` で抽出すると、設問も擬似言語も崩れずに読める。
入っていなければ（`command -v pdftotext`）、macOS なら `brew install poppler`、
Debian/Ubuntu なら `sudo apt install poppler-utils` を案内する。

```bash
pdftotext -enc UTF-8 -layout "<資料フォルダ>/syllabus_fe_ver8_0.pdf" - | less
```

まず `ls` で年度と版を確かめてから読む。下の表は基本情報の例で、ファイル名は
IPA の配布名。利用者が名前を変えていることもあるので、表紙の表記で見分ける。
新しい回が増えていることもある。

| 資料 | 場所 | 何が確定するか |
|---|---|---|
| シラバス | `syllabus_fe_ver8_0.pdf` | 小分類ごとの学習目標と用語例。自作問題の種 |
| 試験要綱 | `youkou_ver5_6.pdf` | 出題範囲の階層、試験時間、科目Bの内訳 |
| 試験用語 | `shiken_yougo_ver5_0.pdf` | 出題で使う用語・表記の統一。言い回しに迷ったら |
| サンプル問題 | `fe_kamoku_a_set_sample_qs.pdf` など | 科目A 60問・科目B 20問＋解答例 |
| 過去問題 | `2024r06_fe_kamoku_a_qs.pdf`・`_ans.pdf` など | 令和5〜8年度の科目A各20問・科目B各6問＋解答例 |

解答例 PDF は「問N 正解」の形なので、転記した問題の正解は正規表現で機械照合できる。
転記したなら必ず照合する。手で写すと1問か2問はずれる。

### 画像の PDF は OCR ツールで読む

問題冊子は画像だけの PDF のことがある（応用情報の `_qs.pdf` は全年度そう）。
`pdftotext` の出力が空か、ページ番号しか出ないなら画像である。`pdffonts` に何も出ないことでも分かる。

このときは **`bunken-ocr-senyo` スキル（OCR ツール）を呼んで読む**。汎用の OCR
（tesseract など）をそのまま流さない。試験問題は数値と記号がそのまま正解に関わり、
0 と 9、ア〜エの取り違えが1字あるだけで問題として成り立たなくなる。

OCR ツールは、資料ごとに専用スクリプト（`ocr_<略称>.py`）を作る作りになっている。
試験問題では次のように当てはめる。

- **専用スクリプトは、区分と冊子の種類ごとに1本**（応用情報の午前で1本、午後で1本）。
  同じ種類の冊子は年度が違っても版面がほぼ同じなので、年度ごとには作らず使い回す。
  版面が変わった年度（試験制度の改訂の前後）に当たったら、そこで作り分ける
- **正解ページには、数値・表・図・擬似言語のある紙面を入れる**。地の文だけの紙面で
  誤り率を測っても、問題で効く誤りが見えない
- **表紙と注意事項のページは除外ページとして書き込む**。問題の本文だけを書き起こす
- **引き継ぎノートを読んでから使う**。PDF のあるフォルダの `OCRツール/` に `引き継ぎ_*.md` があれば、
  その区分の専用スクリプトはもう出来ている。作り直さず、それを新しい年度の冊子に流す
- 書き起こしは PDF のそばに `<PDF の名前>_OCR.txt` として置かれる。以降はこれを読む

書き起こしを転記するときも、**正解は解答例 PDF と機械照合し、数値・式・図表は
元のページ画像と見比べる**。OCR ツールの引き継ぎノートにある「残る誤り」の型を先に読む。
図や表が設問の一部になっている問題は、書き起こしだけでは再現できない。転記せずに見送る。

`bunken-ocr-senyo` が使えない環境（スキルが入っていない、macOS でない）では、
画像の PDF は読めないと利用者に伝え、どうするかを聞く。黙って別の OCR に切り替えない。

### 抽出したテキストは、そのまま貼らない

pdftotext は PDF のルビを独立した行として吐く。`脆弱性` は `ぜい` が前の行に、
`誤謬` は `びゅう`、`虹彩` は `こう`、`秘匿` は `とく` が出る。気づかず設問に貼ると
本文に `ぜい` が紛れ込み、しかも JSON としては通るので取り込むまで分からない。

ページ区切りの `- 12 -` とコピーライト行（`Copyright(c) Information-technology ...`）も
文の途中に割り込む。**貼る前に、ルビ・ページ番号・コピーライト行を取り除く。**

他の区分でも、揃えるものは同じ（試験要綱・シラバス・公開問題と解答例）。
分類の番号と想定出題数はその区分の要綱から起こし直す。下の表は基本情報のもの。

## 問題を書く

取り込み時に検証があり、1件でも通らないと**ファイル全体が弾かれる**。
だから規則は好みではなく、通るための条件だと思って守る。

- `category` は 1〜23 の番号。必須
  **番号はアプリの分類マスタ（`<アプリ>/data/categories.py`）が正**。科目B（旧午後）の
  ように中分類とは別に番号を振ってある分類は、自分で振り直さず、マスタを読んで
  その番号を使う。番号がずれていても科目さえ合っていれば取り込みは通ってしまい、
  「情報セキュリティ」の見出しの下に経営戦略の解説が出る、というずれ方をする
- `topic` はシラバスの**小分類名**。これも**マスタの `TOPICS` が正**（下の節を読む）
- `subject` は `"A"`（知識）か `"B"`（技能・擬似言語）。既定は `"A"`
- `choices` に **ア／イ／ウ／エの記号を入れない**。表示側が付けるので、入れると二重になる
- `answer` は **0 から数える**。1始まりで書くと範囲外か別の選択肢が正解になる
- 選択肢は 2〜10 個、重複なし。**科目Aは必ず4択**、科目Bは本番同様 6〜10 択
- `difficulty` は 1〜3。用語の意味を知っていれば解けるものが 1、
  知識を組み合わせるか計算が要るものが 2、複数分野にまたがるか手順が長いものが 3。
  迷ったら 2
- `source` は必ず書く。あとで「これは公式に裏付けがあるのか、自分で作ったのか」を
  見分けるため。書き方は下の「source はシラバス本文の見出しを写す」の節のとおり
- キー（id）は書かない。アプリが払い出す

**自作問題は正解の位置を散らす**。全部アになっていると、内容を読まずに当たってしまう。
作りながら散らそうとすると、無意識に正解を先頭に置くので偏る。**最後にまとめて
機械でシャッフルし、分布を数えて確かめる**のが確実である。

シャッフルを安全にするために、**`explanation` に「アは〜」と選択肢の記号を書かない。**
「〜は選択ソートの計算量である」のように内容で指す。記号で書くと、シャッフルのたびに
解説を書き換えねばならず、1語でもずれると解説が別の選択肢の話をすることになる。
「最初の選択肢」「上から2番目」のような順序への言及も同じ理由で書かない。
シャッフル前に `[アイウエ]\s*(は|を|が|と|の)` で機械的に走査して、残っていないか確かめる。

位置を散らしても、**正解だけが長ければ読まずに当たる**。長さもそろえる（下の節）。

**転記した問題は選択肢の順を変えない。** IPA の解答例と照合できなくなる。
正解が偏っても、そちらは検証可能であることを優先する。

**図が本質の問題は作らない**。流れ図、アローダイアグラム、三目並べの盤面、
回路図。テキストに落とすと問題として成立しない。

擬似言語は `stem` に改行と全角スペースの字下げでそのまま書く。表示側が整形を保つ。
**半角スペースで字下げしない**（表示で潰れる）。記号も IPA の記述形式に合わせて
全角を使う（`－ ＋ × ÷ ＜ ＞ ＝ ≦ ≧ ←`、剰余は `mod`、整数の除算は `÷ 2 の商`）。
既にあるファイルから1問を読んで、記号と字下げを合わせてから書き始める。

**自分で書いた文に、日本語以外の文字が混じることがある。** 「группы」「четвёртый」
「점수」のような語が、意味の通る位置に紛れ込む。JSON としては通り、読んでも気づきにくい。
書き出したら `[\u0400-\u04FF\uAC00-\uD7AF]` で機械的に走査する。

### 小分類は、アプリの分類マスタが正

`topic` に入れるのはシラバスの小分類名だが、**その一覧と並び順の正はシラバスPDFではなく
アプリの分類マスタ（`<アプリ>/data/categories.py` の `TOPICS`）に置く。**

シラバスPDFから自分で小分類を起こすと取りこぼす。見出しの番号の後が半角の `.` の
ところと全角の `．` のところが混在していて、`^\s*(\d+)\.` で拾うと後者が落ちる。
基本情報では中分類17の「業務プロセス」だけがこれに当たり、96個あるはずが95個になった。
1個足りないことは、数えてマスタと突き合わせるまで分からない。

```bash
python3 -c "
import importlib.util
spec = importlib.util.spec_from_file_location('c', '<アプリ>/data/categories.py')
m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
for c, ts in sorted(m.TOPICS.items()): print(c, ts)
"
```

マスタに無い小分類名を書くと、科目さえ合っていれば取り込みは通る。しかし学習モードの
並び順はマスタの順で決まり、**マスタに無い小分類は末尾に回される**ので、学ぶ順が崩れる。

### source はシラバス本文の見出しを写す

転記した問題は「令和6年度 科目A 問35」「サンプル問題 科目B 問19」。

自作問題は **`シラバス Ver.8.0 中分類{category} {小分類名}（n）{項目名}`**。
科目Bは出題範囲が要綱にあるので
**`試験要綱 Ver.5.6 科目B 出題範囲 {category−100} {出題範囲名}`**（項目名は付けない）。

この `（n）項目名` は、**シラバス本文に実在する見出しをそのまま写す。** 思い出して書くと
ずれる。実際に起きたずれは次の形だった。

| 書いてしまったもの | 本文にある見出し |
|---|---|
| アルゴリズム（2）整列 /（3）探索アルゴリズム | アルゴリズム（2）代表的なアルゴリズム |
| データ構造（3）スタックとキュー | データ構造（2）データ構造の種類 |
| 入出力デバイス（1）入出力制御の方式 | 入出力デバイス（1）入出力インタフェース |
| サービスの運用（2）サービスデスク | サービスの運用（3）サービスデスク |

原因は、本文の階層が「`N.` 小分類 → `（n）` 項目 → `①` 細目」の三段になっていて、
**①の細目名を（n）の位置に書いてしまう**ことである。整列や探索やスタックは①の名前で、
（n）のレベルには存在しない。番号だけがずれている例も混ざる。

だから書く前に、小分類ごとの `（n）項目名` の一覧を本文から起こして対応表にし、
書き出したら全件を機械で照合する。**項目名の前に全角スペースを入れない**
（`（15） インシデント管理` は本文の `（15）インシデント管理` と一致しない）。

```bash
# 小分類ごとの （n）項目名 を本文から起こす。全角の ．にも当てる
pdftotext -enc UTF-8 -layout "<資料フォルダ>/syllabus_fe_ver8_0.pdf" - |
  grep -nE '^\s{0,3}[0-9]+[.．]\s*\S|^\s*（[0-9]+）\s*\S'
```

**`source` が指す小分類と `topic` は一致させる。** 食い違っていたら、`topic` の割当てが
内容と合っていない合図である。たとえば WBS の問題を `topic` に「プロジェクト
マネジメント」と置くと、本文では WBS が「プロジェクトのスコープ」にあるため食い違う。
`topic` を正すのが筋で、**`topic` は同期の鍵（subject ＋ category ＋ stem）に入らない
ので、付け替えても解答履歴は切れない。** ただし移動元の小分類が10問を割るので、
あわせて補充する。

### 誤答の作り方

混同しやすい近い概念を置く。でたらめな誤答を並べると消去法で解けてしまい、
解けたのに何も身についていない状態になる。

計算問題なら「式を取り違えたときに出る値」を並べる。
稼働率なら MTTR÷(MTBF+MTTR) のように、順序を逆にした値が自然な誤答になる。

### 選択肢の長さをそろえる

**正解だけが長くなる。** これは意識していても起きる。正解は正確に書こうとして限定や
根拠の節が増え、誤答は「違う」と分かれば足りるので短く済ませてしまう。結果として、
**中身を読まずに一番長い選択肢を選ぶだけで当たる問題**ができる。

基本情報で実際に測った値を置く。自作847問では正解が誤答より平均 13.6 字長く、
**一番長いものを選ぶだけで 87.2% 当たった**（4択なので偶然なら25%）。
同じ尺度で IPA の公開問題は 41.5%、正解と誤答の字数差は平均 1.6 字で中央値は 0 字だった。
IPA の問題は正解も誤答も同じ粒度で書かれている。そこが決定的に違う。

```
正解  74字: ソフトウェア自体は製造物に当たらないと解されているが，欠陥のあるプログラムを…
誤答  21字: 損害が生じても製造した者の責任は問われない
誤答  19字: ソフトウェアは常に製造物として扱われる
誤答  14字: 適用されるのは食品に限られる
```

そろえ方は二つある。**誤答に同じだけの肉付けをする**ほうが問題としては良くなる。
近い概念を正確に説明した文になるので、誤答そのものが学びになる。
**正解から限定や根拠を削る**ほうは速いが、正解の記述が雑になりやすい。

限定や根拠は `explanation` に書く場所がある。選択肢は、正解も誤答も
**同じ粒度の言い切り**にそろえ、理由づけは解説に回す。

書き出したら機械で測る。**正解が最長である割合が、選択肢数から決まる期待値
（4択なら25%）の2倍を超えていたら書き直す。**

```bash
python3 -c "
import json, statistics as st
rows = [x for x in json.load(open('<区分>_questions.json', encoding='utf-8'))['questions']
         if x['subject'] == 'A']
d = [len(x['choices'][x['answer']]) - st.mean(
        [len(v) for j, v in enumerate(x['choices']) if j != x['answer']]) for x in rows]
hit = sum(len(x['choices'][x['answer']]) == max(len(v) for v in x['choices']) for x in rows)
print('正解−誤答の平均', round(st.mean(d), 1), '字 / 正解が最長', round(hit / len(rows) * 100, 1), '%')
"
```

## 技術解説は別のスキルで書く

学習モードで読ませる技術解説（`notes`）は、このスキルでは作らない。
`ipa-notes` スキルに、長さ・順番・書き方・並び順の決まりがまとまっている。

問題と解説をそろえるために1点だけ合わせる。**`topic` はシラバスの小分類名を
そのまま入れる**（「情報セキュリティ」「データベース設計」など）。学習モードは
小分類の一致で「読んだ解説と同じ範囲の問題」を選ぶので、ここが揃っていないと
解説を読んだ直後に別の範囲が出る。

## 過去問と自作の割合

**全体で、転記6割・自作4割**にする。転記は正解が IPA の解答例で裏付けられ、
自作は公開問題の無い小分類を埋められる。どちらかに寄せると、
裏付けが弱くなるか、範囲に穴が空く。

転記できる公開問題は限りがある。

| | サンプル | 過去問（令和5〜8年度） | 計 |
|---|---|---|---|
| 科目A | 60問 | 20問 × 4年 = 80問 | 140問 |
| 科目B | 20問 | 6問 × 4年 = 24問 | 44問 |

図が本質の問題は転記できないので、実際に使えるのは科目Aで120問前後。
**これを6割と見ると、科目A全体で200問**になる。

**分野ごとには 6:4 にならない。** 公開問題は本番の出題比率どおりに偏っていて、
セキュリティは毎年数問出るが、法務や技術戦略は数年に1問しかない。
公開問題の多い分野は転記を厚く、薄い分野は自作で埋める。
薄い分野が自作10割になるのは避けられない。

**シラバスを網羅するなら、6割は保てない。** 転記できるのは科目Aで120問前後が上限で、
小分類すべてを10問ずつ埋めると960問前後になるので、自作が9割近くになる。これは
問題集の規模を選んだ結果なので、避けようがない。**どちらを選ぶかは先に決めて伝える。**

| | 問数 | 転記の割合 | 得られるもの |
|---|---|---|---|
| ひととおり揃える | 科目A 200問前後 | 6割 | 正解の裏付けが厚い。小分類に穴が残る |
| シラバスを網羅する | 科目A 960問前後 | 1割強 | どの小分類からも10問のラウンドが組める |

網羅を選んだときは、裏付けの弱さを**出典の照合**で補う。自作の `source` を全件
シラバス本文と機械照合し、範囲外の話題を書いていないことを確かめる（下の節）。

## 分量の目安

| 依頼 | questions |
|---|---|
| 数問だけ、試しに | 言われた数 |
| 分野をひとつ | その中分類の小分類ぶん（小分類 × 10問） |
| ひととおり揃える | 科目A 200問前後・科目B 20問以上 |
| シラバスを網羅する | **小分類すべて × 10問**（基本情報なら科目A 960問前後） |

### 小分類ごとに10問が、網羅の単位になる

学習モードは、解説を読ませたあと**同じ小分類から10問**出す（`LearningRound.QUESTION_COUNT`）。
解説がある小分類の問題が10問に届いていないと、その分だけ短いラウンドになる。だから
**解説を1本書いたら、その小分類に10問**が対になる。解説だけ足しても、問題が0問の小分類は
解説の一覧にも出ない（`pick_note` が問題のある小分類に絞る）。**解説と問題はセットで作る。**

### 問題数を増やしても、本番の配分は崩れない

中分類ごとの問数を想定出題数に合わせる、という配分の話と、小分類を10問ずつ埋める話は
衝突しない。**出題の抽選は `category.exam_weight`（本番の想定出題数）だけで中分類を選び、
その分類に何問あるかは重みに入らない**（`<アプリ>/selection.py` の `_category_weights`）。

```python
base = category.exam_weight   # 問題数ではない
```

だから、小分類の数が多い中分類を10問ずつ埋めても、その分類が出やすくなることはない。
基本情報の中分類14は小分類が11個あるので全網羅で110問になるが、本番の想定は3問のままで、
増えた分は「14が当たったときの中身が尽きにくい」という効果になる。

網羅を目指すかどうかは使う人が決めること。**指定がなければ、ひととおり揃えるのか
シラバスを網羅するのかを先に聞く。** 網羅は分量が5倍ほど違う。

### 書き切れない量になったら

中分類ごとに書いて、**書くたびに検証して本体へ足す**。最後に一度にまとめようとすると、
検証で弾かれたときに戻る先が遠い。部品は資料フォルダの下に `作業中/` を作って残しておく
（`new_c14.json` のように中分類が分かる名前）。次に一部だけ書き直すときに使える。

正解位置のシャッフルだけは最後に一度、全件に対して行う。
そのとき**既存の問題（解説に記号を書いてあるかもしれないもの）は対象から外し、
今回書いた分だけを動かす**。対象の stem を部品ファイルから集めれば分けられる。

## 書き出したら、機械で確かめる

目で読んで気づける誤りは少ない。1件でも通らないと取り込みでファイル全体が弾かれるので、
**書き出すたびに次を機械で確かめる。** 中分類ごとに書くなら、そのたびに回す。

1. 解説がある小分類の問題が **10問以上**あるか
2. 解説が無い小分類、問題が無い小分類が残っていないか
3. `topic` が**アプリの分類マスタ `TOPICS` にある**名前か
4. 自作の `source` が**シラバス本文の「小分類＋（n）項目名」と一致**し、かつ
   **`topic` と同じ小分類を指して**いるか
5. `stem` の重複（空白と全角半角をそろえて正規化して突き合わせる）
6. 科目Aが4択、`answer` が範囲内、選択肢に重複や空がないか
7. 科目Bの選択肢が4〜10個、`answer` が範囲内か
8. 選択肢の先頭にア〜コの記号が入っていないか
9. **日本語以外の文字**（キリル文字・ハングル）が混じっていないか
10. 正解位置の分布（科目Aは4つにほぼ均等か）
11. **正解が最長である割合**（4択なら25%に近いか。50%を超えたら選択肢の長さを直す）
12. 転記と自作の比
13. `python3 -m json.tool` で構文が通るか

あわせて、**本体へ足す前と後で差分を照合する。** 件数、消えた問題の数、既存の問題で
変わったものの数を出す。意図した以外のものが動いていたら戻す。控えを別名で取っておく。

```bash
cp <区分>_questions.json 作業中/<区分>_questions.before_<何をするか>.json
```

## 出来たら

**書き出し先は資料フォルダ**（指定があればそこ）。区分と中身が分かる名前を付ける
（`fe_questions.json`・`ap_questions.json`）。更新するときは同じ名前へ上書きし、
前の版を残したいときは控えを別名で取る。解説のファイル（`<区分>_notes.json`）とは
名前で見分けられるようにしておくと、取り込みのときに取り違えない。

書き出したファイルの場所を伝える。取り込みは管理用の ID（is_admin）で入った人が画面から行う。ほかの ID には入口が出ない。

```
アプリ → 問題の管理 → JSONを取り込む → ファイルを選ぶ
```

取り込みは**鍵で突き合わせる同期**なので、変わっていない問題はそのまま残り、
解答履歴も途切れない。消えるのは、ファイルから無くなった問題と、stem を書き換えて
別物になった問題の履歴である。確定の前に追加・更新・変更なし・削除の件数が出るので、
**削除の件数が想定より多ければ取り込まない。** 書き出した範囲が足りていない合図である。
分野ごとの理解度（正答率・苦手判定）は別に積み上げているので、どちらでも残る。
