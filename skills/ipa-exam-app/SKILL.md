# IPA区分の対策アプリを作る

区分ごとにアプリを1本作る。既存のものを書き換えて区分を移し替えるのではなく、
**必要になった区分のアプリを、そのつど足す**。前の区分のアプリはそのまま残るので、
基本情報を終えて応用情報に移っても、基本情報の記録は消えない。

参照する実装は https://github.com/hirahiratriangle/hirahira_room の `fe/`（基本情報版）。
作る前にこれを読むと、出題ロジックと平滑化の実装が揃う。手元に無ければ
`git clone --depth 1` で作業用の一時フォルダへ取ってきて読む（利用者のプロジェクトには混ぜない）。

## 作る前に確かめること

**区分**（応用情報技術者試験、システムアーキテクト試験、など）と、
**手元の資料**。資料が無いと推測で作ることになり、範囲外の分類が入る。

必要なのは3つ。IPA のサイト（https://www.ipa.go.jp/shiken/ の各区分のページ）からいずれも無償で落とせる。

- **試験要綱** — 出題範囲の階層と知識項目例。分類マスタの根拠
- **シラバス** — 小分類ごとの学習目標と用語例
- **公開問題（過去問・サンプル）** — 設問形式と難易度、想定出題数の割り出し

## 資料の置き場所を決める

資料は**使う人が好きなフォルダに集めてある**。場所は決め打ちしない。

1. 依頼の中でフォルダを指定されたら、そこを使う
2. 指定が無ければ、作業ディレクトリの下を `find . -iname '*.pdf'` で探す
3. それでも見つからない、または足りなければ、何が足りないかを伝えて
   置き場所を聞く。**資料が揃うまで作り始めない**

見つけたら、ファイル名と PDF の中身（表紙の「試験要綱」「シラバス」
「Ver.」の表記）で種類と版を見分ける。ファイル名は IPA の配布名のままとは限らない。
以降このスキルで「資料フォルダ」と書いたら、ここで決めたフォルダを指す。

PDF は `pdftotext -enc UTF-8 -layout` で読む。入っていなければ
（`command -v pdftotext` で確かめる）、macOS なら `brew install poppler`、
Debian/Ubuntu なら `sudo apt install poppler-utils` を案内する。

## 作るもの

利用者の Django プロジェクトに、アプリを1つ足す形。サーバもDBも増やさない。
プロジェクトが無ければ、`django-admin startproject` で最小のものを作ってから足す。
どちらにするか、どこに作るかは作り始める前に確かめる。

参照実装の `fe/` は、載っているサイトの次のものに頼っている。コピーしたり
真似たりするなら、利用者のプロジェクトにあるかを確かめ、無ければ用意する。

- **`base.html`** — テンプレートはすべて `{% extends 'base.html' %}`。Bootstrap 5 と
  Font Awesome 5 を読み込み、`title`・`head`・`header`・`contents`・`extra_js` の
  ブロックを持つもの（`content` ではなく `contents`）。上部に固定ナビバーがある前提で、
  ヘッダーに `padding-top: 5rem` を入れている。ナビバーが無ければ詰める
- **ログイン** — ビューは `LoginRequiredMixin` を継承し、`LOGIN_URL` は django-allauth の
  `account_login`。ログインの仕組みが無いなら、`django.contrib.auth.urls` を足すか、
  ミックスインからログイン必須を外す。どちらにするかは利用者に聞く
- **設定値** — `FE_MAX_UPLOAD_BYTES`（取り込みの上限。8MB）と、それより大きい
  `DATA_UPLOAD_MAX_MEMORY_SIZE`。区分ごとに接頭辞を変える
- **管理画面** — 管理用の ID は Django の管理画面で付ける。`createsuperuser` まで案内する

1. **分類マスタ** — 要綱の出題範囲をそのまま写す。IPA の区分はどれも要綱に
   出題範囲があるので、自分で分類を起こす必要はない
2. **想定出題数** — 中分類ごとの出題数は IPA が公表していない。
   サンプル問題と過去問から割り出し、**合計が本番の出題数と一致する**ようにする
3. **問題と技術解説** — JSON で持つ。プログラムに埋め込まない。
   作り方は `ipa-questions` スキルにある
4. **計算問題のテンプレート** — 数値を変えれば何度でも解ける型。区分ごとに頻出計算が違う
5. **出題ロジック** — 下の節
6. **画面** — 1問1答の演習、解説を読んでから解く学習モード、
   分野別の正答率、解答履歴、出題設定
7. **テスト** — 重点出題が実際に苦手分野へ寄ることを検証する

## 出題ロジック

分野を選ぶところと、その中で1問を選ぶところの2段になっている。

### どの分野から出すか

```
重み ＝ 想定出題数 ×（0.3 ＋ 2.0 × 苦手度）
```

本番比率だけで出すと、得意になった分野も同じ頻度で出続ける。
苦手度だけで出すと、本番で1問しか出ない法務ばかり出る。
掛け合わせると、本番の重みを保ったまま苦手が厚くなる。得意なら0.3倍、
まったく解けないなら2.3倍。未着手の分野はさらに1.6倍する。

### 苦手度をどう測るか

素の正答率をそのまま使わない。2問解いて2問外しただけで正答率0%になり、
その分野ばかり出るようになってしまう。

```
平滑化した正答率 ＝ (正解数 ＋ 5 × 0.6) ÷ (解答数 ＋ 5)
苦手度 ＝ 1 − 平滑化した正答率
```

合格ライン相当の 0.6 へ、5問ぶんだけ引き寄せてから比べる。
解答数が増えるほど平滑化の影響は小さくなり、実測値に近づく。

### 分野の中でどの問題を出すか

未出題を常に最優先にすると、落とした問題は未出題が尽きるまで戻ってこない。
200問あれば全部を一度ずつ解き終わるまで復習されない。

そこで**まちがえた問題は、ほかを数問はさんでから未出題より先に戻す**。
直後に出すと答えを覚えているだけで解けてしまうので、間はあける。
何度も落としている問題ほど間隔を詰める（5問 → 3問 → 2問）。

未出題も期限の来た復習も無いときは、正解済みで久しく解いていないものを回す。

## データの持ち方

成績は**アプリ内の ID（Learner）ごと**に持つ。サイトの
アカウントとは紐づけない。ID は本人が決める文字列で、入口（基本情報版なら /fe/）で入力すると
セッションが覚え、ダッシュボードは /fe/<ID>/ で開く（ほかの ID のものは404）。
URL の接頭辞は区分ごとのアプリ名にする（応用情報なら /ap/ など）。
合言葉は無く、ID を入力した人を本人として扱う。

**問題と解説は全 ID で共有**し、JSON の取り込みで**一括差し替え**する。
JSON は Claude が作るもので、利用者が自分で用意することはない。そこで取り込み・
書き出し・問題の一覧は**管理用の ID（is_admin）だけ**に許し、ほかの ID には
画面の入口も出さない。管理用にするのは Django の管理画面から。
画面に入力欄は置かない。更新経路をファイル1本に絞ると、手元のファイルと
出題内容がずれない。

取り込むと古い問題・解説と、それに紐づく全 ID の解答履歴は消える。データが増え続けないため。
**残すのは分野ごとの理解度**（解答数・正解数・最終解答日）で、解答のたびに
別テーブルへ積み上げる。問題を入れ替えても苦手判定は続く。

分類マスタと計算問題のテンプレートはアプリ全体で共有する。

## 画面

- **入口** — ID を入力して入る／新しく作る
- **ダッシュボード（/fe/<ID>/）** — 全体の正答率、苦手な分野、未着手の分野、学習日数
- **1問1答** — 出題モード（おまかせ／本番比率どおり／苦手分野だけ／復習／分野指定）
- **学習モード** — 技術解説を時間を決めて読み、そのあと同じ範囲から10問。
  読む段階では設問も選択肢も見せない。答えを覚えるのではなく中身を読ませたいため
- **分野別の正答率** — 中分類ごとの成績と、重点出題での比率
- **解答履歴** — まちがえた問題を見返す
- **問題の管理**（管理用の ID のみ） — 一覧と JSON の取り込み・書き出し

どのページにも同じヘッダーを置き、どこからでも同じ場所へ戻れるようにする。

## 分析の単位は中分類

情報処理技術者試験の出題範囲は、分野（3）→ 大分類 → 中分類 → 小分類 の階層。

小分類は細かすぎて、解答数が貯まらず正答率が安定しない。
分野は粗すぎて、次に何を勉強すべきかが決まらない。
**中分類**なら、弱点が分かれば次の一手が決まる。基本情報で23個。

## 一度に頼むなら

```
IPAの◯◯試験の対策アプリを作ってください。手元に試験要綱・シラバス・
過去問の PDF があります。既存の Django プロジェクトに追加してください。

1. 要綱の出題範囲を、そのまま分類マスタにする
2. サンプル問題と過去問から、中分類ごとの想定出題数を割り当てる
   （合計が本番の出題数と一致するように）
3. 中分類を全網羅する問題と、小分類ごとの技術解説を JSON で用意する。
   過去問から転記した問題と自作したものは、出典フィールドで区別する
4. 数値を変えれば何度でも解ける計算問題はテンプレート化する
5. 出題は重み付き抽選にする。重み ＝ 想定出題数 ×（0.3 ＋ 2.0 × 苦手度）
   苦手度は、正答率を 0.6 へ 5 問ぶん平滑化してから求める
6. 1問1答の演習、解説を読んでから解く学習モード、分野別の正答率、
   解答履歴の画面を作る
7. 重点出題が実際に苦手分野へ寄ることを、テストで検証する
```

## 区分ごとに違うところ

基本情報のものをそのまま持ってくると、次が合わなくなる。

- **中分類と想定出題数** — 区分ごとに違う。要綱から起こし直す
- **科目の呼び方** — 基本情報は科目A／科目B。応用情報は午前・午後、
  高度区分は午前I・午前II・午後I・午後II。選択肢を区分に合わせる
- **計算問題の型** — 頻出の計算が違う
- **画面の見出し** — 「FE 基本情報対策」のような文字列が各所にある

一方、分野（テクノロジ系・マネジメント系・ストラテジ系）は共通キャリア・
スキルフレームワークのもので、どの区分でも同じ。ここは触らなくてよい。

## 公開して運用する

既存サイトにアプリを1つ足す形なので、デプロイ先も増えない。
サイトにログインの仕組みがあれば、全画面ログイン必須にする（入口で締める）。
そのうえで成績はアカウントではなくアプリ内の ID ごとに分ける。
公開しない、自分の PC だけで使うなら `runserver` で足りる。

問題データをコードから切り離しておくと、あとで作り直すのも他の区分に
流用するのも楽になる。**貯めるのは成果物ではなく、作り方**。
